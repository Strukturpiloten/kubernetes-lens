# ADR0093: Source-bound checked capture-size status

Status: Proposed private source-only successor to the accepted V30/V12 source.
Focused inert controls and canonical formatting are source evidence only. Primary
review/integration, complete gate and any separately adopted attempt remain pending.
No native execution, automatic retry or source-custody authority follows.

## Evidence and smallest decision

V30 remains failed, spent and independently known retired. Its first failure was
k4.m, the server-side Deployment dry-run: obtained command0, native wrapper125,
stdout collector1 and stderr collector0. Strict response validation was not reached.
The retained catalogue has no failed dry-run stdout or dd/stat attribution. Collector1
therefore proves neither over-cap output nor any particular utility, filesystem,
clock, readiness or CNI cause. This successor never reclassifies that historical1.

Use only the stat size already obtained in the existing ordinary capture helper.
After the unchanged numeric-form guard, a size comparison strictly above its
unchanged selected maximum exits that existing helper process with fixed status23.
Below/equal sizes retain success. Other failures/refusals retain generic1; the
original final comparison remains so reached arithmetic errors stay opaque rather
than becoming over-cap evidence. No data, stat, copy, command, role or actor is added.

An explicit helper-process exit is necessary: the inherited ERR trap normalizes a
nonzero function return to1 in this context. Do not clear or weaken that trap.
Every production capture_stream call remains one of the original two process
substitutions inside native(). No parent/main call or new subprocess is introduced.
Only this checked-over-cap branch exits23. Fixed dd/stat errors, including a tool
return23, are still normalized to1 by their original failure paths.

native() is byte-exact: it retains obtained command status, waits both collectors,
records their raw statuses, poisons work and returns125 if either failed. A helper23
thus cannot override an earlier immutable failure or erase the command's status.
Command23 with successful collectors remains an ordinary command failure, not size
attribution. Existing failure/cleanup priority and clock order remain unchanged.

## Raw field semantics and no wire-version bump

Keep V12 spec/result pairing, P2 bidirectional intent binding, k4 sites, exact keys,
integer status ranges and all public/private shape contracts unchanged. The
collector fields have always meant obtained raw POSIX helper wait statuses, not a
closed semantic enum. Status23 now records an actual helper exit23 in the same
field; native wrapper125 and zero/nonzero acceptance retain their existing meaning.
No new field, decoder label, default, namespace or enum is introduced, so no wire
version bump is needed for this source-only diagnostic.

Interpret23 as the checked size guard ONLY with the exact authenticated new receiver,
ordinary capture-helper invocation and selected cap. It is not a global meaning for
all23 statuses or all V12 records; older raw23 remains opaque. Even with that binding,
it proves the helper's checked size exceeded the cap, not why it did, the producer's
uncapped total output, a validated response, process-exec identity or runtime cause.
Host decoding and public descriptors continue to preserve raw numbers and redaction.
Remaining1 is unavailable attribution, not proof that the stream fit: copy/stat
failure may have prevented the size check from being reached.

The new exact source-enrollment hash authenticates this implementation. A strict
current-to-accepted-V12 inverse recovers65408 bytes /SHA256
`e5d4870bc9d3994f9c73d54cbeeb5abe322c9511a973f3f1d8870dd05b16a0b5` before every
unchanged predecessor inverse. Old controls explicitly select that frozen view;
new controls explicitly use current source. Old raw records, assertions, negative
expectations, names and registered314 stderr patterns remain intact.

## Qualification boundary

Focused boundary tests use fixed dd/stat DATA for below/equal/over-cap, malformed
and arithmetic-error forms, copy/stat/ticket/redirection failure and original
zero/nonzero parity. Inert extracted native() helper tests preserve the real ERR
policy and existing process-substitution context, proving raw23 propagation,
wrapper/command precedence and earlier-failure custody. Mock worker/parent tests
preserve raw fields, shared budgets and public redaction. Static controls preserve
all old assertions, exact receiver history, calls, traps, budgets and canonical fit.
No real tool, host/cluster, constructor, renderer, source capture or native attempt
is run by those controls. Complete gate and later exact-source adoption remain
primary-owned, with V30 history and retirement independent.

No software, binary, image, dependency or installer changes; existing BoxFerry tool
and Renovate ownership are unchanged. Current source and native qualification are
different evidence: a passing source candidate authorizes no later attempt.
